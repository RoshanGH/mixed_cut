## 📅 Phase 2 — 音频驱动反向混剪（「给口播配画」）

### 场景

用户已经积累一定的分镜素材库（口播/产品介绍视频已经被 AI 分析过）。**新流程**：

```
用户上传一段【完整产品介绍音频】（mp3 / m4a / wav / 也可以上传 mp4 取音轨）
  ↓ Whisper ASR 识别音频内容（按句子拆段，带时间戳）
  ↓ AI 对每个音频段从分镜库挑选语义匹配的画面
  ↓ 按音频时间线编排选中分镜的画面（音频原音保留作为最终音轨）
  ↓ FFmpeg 合成新广告视频
```

**核心创新**：之前的混剪是「文本 prompt → 选分镜组合」，新功能是「**音频 → AI 配画面**」。本质是**给口播配镜头**。

### 设计决策点（开发前必须想清楚）

| 决策点 | 候选方案 | 默认推荐 |
|--------|---------|---------|
| **音频来源** | A. mp3/m4a/wav；B. mp4 取音轨；C. 都支持 | C |
| **输出音轨** | A. 完全替换为上传音频（分镜静音）；B. 上传音频为主 + 分镜原声做 BGM 弱化；C. 用户选 | A（MVP），C（后续）|
| **画面节奏匹配** | A. 严格按音频每句映射 1 分镜；B. AI 智能编排（一对多 / 多对一）；C. 分镜时长尽量等于音频段时长，超长截短，不足留尾帧 | C |
| **匹配算法** | A. 纯文本 embedding 相似度；B. 语义类型 + 关键词；C. AI 大模型直接选；D. B + C 混合 | D：先按语义类型粗筛 → AI 精选 |
| **画面不够用** | A. 报错让用户补；B. 允许重复使用分镜；C. 兜底用"过渡"分镜 | B + C：优先非重复，不足时允许重用 |
| **匹配范围** | A. 仅当前项目分镜；B. 全局分镜库 | A（MVP），B（用户可选）|

### 技术路径

#### Phase A — MVP（核心走通）

1. **音频导入入口**
   - 新建「音频驱动」工作区 or 在「混剪方案」加入口
   - 支持拖拽 mp3/m4a/wav/mp4，FFmpeg 提取音频统一转 16kHz mono wav

2. **音频 ASR**
   - 复用 `ASRService.transcribe(videoPath:)`
   - 输出 `[TranscriptionSentence]`（带时间戳）

3. **匹配服务 `AudioMatchService`**（新建）
   - 输入：上传音频的 sentences + 候选分镜列表
   - 流程：
     - Step 1：按语义类型 + 关键词粗筛（每段音频选 3-5 个候选分镜）
     - Step 2：AI 大模型精选（一次调用，喂分镜目录 + 音频 ASR，输出每段音频的最佳分镜 ID）
   - 输出：`[(audioSegment, matchedSegmentID, useStart, useEnd)]`

4. **数据模型**
   - 新增 `AudioGuidedScheme`（或扩展 `MixScheme` 加类型字段）
   - 字段：`audioFilePath` / `audioASR` / `matchedSegments`

5. **合成 service**
   - 复用 `FFmpegRunner.concat`
   - 把分镜画面按时间轴拼接 + 上传音频替换音轨
   - 注意：分镜时长 ≠ 音频句长时，trim 或留尾帧

6. **UI 进度展示**
   - 三步：上传 ASR → AI 匹配 → 合成
   - 每步显示进度 + 当前在做什么

#### Phase B — 增强

- 用户手动调整匹配（拖拽换镜，类似时间线编辑器）
- 匹配置信度展示（低置信度提示用户检查）
- 一次上传多个音频，对比生成不同版本
- BGM 叠加（上传音频 + 原分镜 BGM 弱化）

### 风险与边界

| 风险 | 说明 |
|------|------|
| **画面节奏与音频不同步** | 分镜时长 ≠ 音频句长，必须 trim 或留尾帧；MVP 用方案 C |
| **匹配质量天花板** | 取决于分镜库丰富度。库小（< 50 个）时只能找差强人意的镜头；UI 要明确提示「素材不足」 |
| **画面口型对不上** | 必然对不上 — 文案上要明确这是「**素材配画**」不是「换脸/对口型」|
| **同一镜头反复出现** | 视觉差，需要去重逻辑（连续 2 段不用同一镜头）|
| **音频含 BGM 干扰 ASR** | 复用现有 ASR 三层降级机制 + 提示用户上传纯净口播 |
| **AI 匹配成本** | 每次匹配 1 次大模型调用（音频 sentences × 候选分镜目录），prompt 较长。需要算 token 成本 |

### 入口与时机

- 等当前 v0.2.x 体验稳定后启动（用户反馈 ASR / 分镜 / 导出已经够用）
- 启动前先做：分镜库「全局视图」（让 Phase A 的 MVP 默认范围设到「当前项目」前，全局视图先准备好）

## 📅 Phase 3 — 成片音轨分离（已讨论待立项）

### 场景

成品 MP4 反向拆出 **口播 / BGM / 音效** 三轨。用于：
- 替换 BGM（不同平台投放）
- 提取纯口播配新画面
- 复用音效素材

### 技术路径

- Demucs (htdemucs) 本地 PyTorch 模型，集成方式参照 whisper.cpp bundle
- 或 Demucs 转 CoreML + Apple Silicon 加速（最理想）
- 或调用 LALAL.AI / Moises 云端 API（要钱、要网络）

详细分析见之前讨论。
