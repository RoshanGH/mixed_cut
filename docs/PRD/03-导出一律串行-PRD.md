# PRD 03 · 导出一律串行（不再并发）

> 目标：Windows 版行为对齐 macOS 版 v0.7.x。
> 参考截图（导出页整体）：`../screenshots/export.png`

---

## 0. 一句话定义

**所有导出任务一律串行执行——一条一条导，不再并发。** 无论是"方案导出""单分镜/批量分镜导出"还是"配音组合导出"，都排成一个队列、上一条完成再开下一条。

## 1. 为什么

导出走 FFmpeg 硬件编码 + 拼接，单条就吃不少 CPU/GPU；并发多条会**占满机器**、互相抢资源反而更慢、还可能让 app 卡顿。改成串行后机器始终留有余量，进度也更可预期。（这是用户明确要求：「所有的导出都不再并发了，一个一个导就完了」。）

## 2. 适用范围（所有导出路径）

以下每一条路径的并发度都必须是 **1（串行）**：
- **混剪方案导出**（选中的方案 × 各分镜排列组合逐条出片）。
- **单分镜 / 批量分镜导出**（分镜库里多选分镜 → 各自单独出片）。
- **配音组合导出**（每分镜「原声 + 勾选的改写版」排列组合逐条出片，组合规则见 [PRD 02](./02-配音变体参与排列组合-PRD.md)）。

## 3. 行为与 UI 表现

- **队列串行**：把所有待导出条目排成一队，**完成一条再开下一条**；任意时刻只有 1 条在编码。
- **顺序**：按方案顺序 / 分镜顺序依次导出。
- **进度文案**：导出过程中显示「**串行导出中… {已完成}/{总数}**」，实时递增。
- **说明文案**（导出前预览处）：如「选中 N 个方案，画面不变，按每个分镜的『原声 + 各改写版』全部排列组合，**串行逐条生成（一条一条导，避免占满机器）**」。
- **可停止**：导出中可点停止，显示「停止中…」，停完当前条后不再继续后续条目。
- **失败不阻塞队列**：某条失败记录错误后继续下一条（不因一条失败中断整批）。

## 4. Windows 实现要点

- 导出用**串行队列**（或线程池大小 = 1）驱动，**不要**用无上限并发 / CPU 核数并发池。
- 进度 = 已完成条数 / 总条数；每条完成后触发下一条。
- 总条数 = 各分镜「参与档数」连乘（见 [PRD 02 §3](./02-配音变体参与排列组合-PRD.md)）——串行导出时这个总数直接决定要排多少条队。

## 5. 验收

- 同时导出多条时，任务管理器里始终只有 **1 个** FFmpeg 编码进程在跑（不是多个并行）。
- 进度文案随每条完成 +1。
- 中途停止：当前条导完即停，剩余不再开始。
