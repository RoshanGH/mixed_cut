## 1. 目标与背景

MixCut 现有的分镜（`Segment`）是按**台词/语义逻辑**切分的——一个逻辑分镜内部，画面上往往已经过了好几个真实镜头（换机位、换人、换场景）。因此**逻辑分镜不是画面连贯的单元，无法直接拿去做画面替换**。

本功能新增一条**画面裂变**维度：

1. 把一条逻辑分镜**再切成有序的物理镜头（分镜头）**；
2. 对**单个分镜头**用**纯自然语言提示词**做 AI 局部编辑（换背景 / 换人物外观 / 换主体 / 换颜色材质等），生成若干**变体**；
3. 用户以**占位式**（每个分镜头位置单选一个版本、顺序不变）把选定的分镜头**重组成一条新的逻辑分镜**，进入分镜素材库，与原分镜**并存**；
4. 新逻辑分镜的下游（排列组合、配音、台词改写、字幕烧录/遮挡、导出等）**全部走既有路线**，与普通逻辑分镜完全一致。

**本功能的边界到"产出新逻辑分镜进库"为止**，不改动任何下游逻辑。

### 1.1 与 2026-06-24 旧 findings 的关系（取代）

旧文档结论是：**只做换背景**，用 `wanx2.1-vace-plus`（VACE）+ macOS Vision 自动抠前景遮罩，≤5s，输出无声。本设计在需求上更宽（任意局部指令编辑，如换发型/换睡衣颜色/换背景画/换主体），VACE 的"抠前景整体遮罩"覆盖不了"改人物身上某一小块"，因此本版：

- **改用指令式编辑模型 `wan2.7-videoedit`**：纯自然语言、无需 mask、无需框选、无需参考图，正好匹配用户"只写一句提示词"的最终决策。
- 保留旧文档的两条硬事实（见 §5 风险）：编辑类模型**输出可能无声**、结果 **URL 24h 过期**。
- 旧文档的 VACE + Vision 抠图"精确换背景/精确换特定商品"方案**降级为未来增强**（见 §8 非目标），不在本版。

### 1.2 "Happy House" 澄清

用户口语中的"Happy House"≈"Happy Horse（快乐马）"，是阿里的**视频生成模型**（文生/图生视频），只能"重新生成一段视频"，**无法保留原分镜动作只改局部**，方向不符，**本功能不使用它**。本功能使用的是**编辑类模型 `wan2.7-videoedit`**。

## 附录：Phase 0 API 实测结论（2026-07-03，GO）

用真实千问 key（`api_key_qwen`）对一段 3s / 720×1280 / 30fps 竖屏食品广告切片实测 `wan2.7-videoedit`，2 条任务均 `SUCCEEDED`：

**接口与工程事实（已验证，直接指导 Phase 3 实现）**
- 端点 `POST .../aigc/video-generation/video-synthesis` + `X-DashScope-Async: enable` → `output.task_id`；轮询 `GET /tasks/{id}` 看 `output.task_status`（PENDING/RUNNING/SUCCEEDED/FAILED），成功取 `output.video_url`（24h 过期）。
- **`media` 支持 Base64 内联**（`{"type":"video","url":"data:video/mp4;base64,..."}`）——**无需 OSS 上传**，Phase 3 走 Base64 即可（切片仅几百 KB）。
- 请求体：`input.prompt` + `input.media[]`；`parameters` 用了 `resolution:"720P"`, `ratio:"9:16"`, `duration:0`(保持原长), `watermark:false`, `prompt_extend:true`。
- 耗时 ~3.5–4 分钟/条。计费字段 `usage.duration=6`（3s 输出，疑似按 2×输出秒计），单价待控制台确认。
- **输出帧数与输入完全一致（90→90，零漂移）**，720P/9:16 保留 → §8.2 的帧对齐降级为纯兜底（drift 实测为 0，仍保留防御）。
- **输出带音轨（aac）**——但按 §8.4 仍一律合回原音频，不依赖变体音轨。

**保真度结论（命门验收）**
- **换背景**（"换成明亮白色厨房，前景不变"）：✅ 优秀——手/产品/字幕逐像素保留，背景干净替换、光照自然。
- **换手里物体**（"馒头→绿瓶雪碧"）：✅ 物体成功替换且背景/景深/框架保留；⚠️ 但因原动作是"两手捏软馒头"，硬瓶被迫跟随该形变 → 不自然。
- **关键使用规律（须落进产品引导/预设）**：替换效果取决于**新物体与原物体的形状/刚性/动作是否兼容**。like-for-like（可乐→雪碧、粉包装→蓝包装、换背景、换颜色/材质）效果好；drastic 且动作不兼容（软物→硬物）会形变穿帮。→ UI 预设与提示应引导用户做同类替换，并说明"变体可预览/删除/重生成"应对偶发穿帮。

**产物**：`~/Desktop/phase0_原片.mp4` / `phase0_换背景.mp4` / `phase0_换物体.mp4`。

## 2. 核心概念与术语

| 术语 | 说明 |
|---|---|
| **逻辑分镜**（`Segment`，现有） | 按台词/语义切分的分镜，本项目最细的持久化剪辑单元。帧号存储（`startFrame`/`endFrame`）。 |
| **分镜头 / 物理镜头**（`PhysicalShot`，新增） | 逻辑分镜内部、按画面变化度切出的连贯镜头。有序（`orderIndex`），记源视频帧区间。 |
| **变体**（`ShotVariant`，新增） | 对某个分镜头做一次 AI 提示词编辑的产物。一个分镜头可有 0..N 个变体。 |
| **占位式重组** | 每个分镜头是一个"坑"，顺序锁死；每个坑**必选且只选一个版本**（原分镜头或它的某个变体）。 |
| **合成分镜**（一条新的 `Segment`） | 把各坑选定的分镜头按序拼接 + 合回原音频，产出的新逻辑分镜。进库、与原分镜并存。 |

## 3. 用户流程（端到端）

**入口（弹窗式工作区）**
1. 分镜素材库里，选中一条逻辑分镜 → 卡片/工具栏出现「分镜头替换」按钮 → 点击进入**分镜头变体工作区**（全屏 sheet）。切割与编辑都在工作区内发生，库列表本身不展开这一层。

**工作区内**
2. 进入后，对该逻辑分镜跑一次画面变化度切分，切出有序分镜头 1→2→…→N 并**持久化**（`PhysicalShot`）。已切过的直接展示（缓存）。
3. 分镜头边界**支持以帧为单位手动调整**（复用现有边界微调交互 `BoundaryAdjustRow` 那套帧级操作）。调整后重算该分镜头的时长与可编辑资格。
4. 选定某个分镜头（时长须落在 `[2s, 10s]`，见 §6）→ 填写提示词（可从预设示例选，见 §7）→ 提交 → 异步生成 → 成功后作为该分镜头的一个**变体**存下。可对多个分镜头做，也可给一个分镜头生成多个变体。

**占位式组合（核心）**
5. N 个位置，顺序 1→2→…→N 锁死。每个位置**必须选、且只能选一个版本**：原分镜头 or 它的某个变体。
   - 例（N=4）：1 号原版、2 号"换雪碧"变体、3 号原版、4 号"换蓝色睡衣"变体。
6. 点「合成」→ 按序拼接选定切片 + **合回原逻辑分镜音频** → 产出一条新 mp4 → 建**新逻辑分镜**（继承台词/语义/关键词/位置类型，标 `sourceSegmentID`）→ 进分镜素材库，**紧挨原逻辑分镜之后**。

**收尾**
7. 新逻辑分镜的下游全部走既有路线（排列组合、配音、台词改写、字幕烧录/遮挡、导出、被手动选用）——与普通逻辑分镜等价。本功能到此结束。

## 4. 数据模型

### 4.1 新增 `PhysicalShot`（@Model）

- `id: UUID`
- `parentSegment: Segment`（关系；反向 `Segment.physicalShots: [PhysicalShot]`，cascade 删除）
- `orderIndex: Int`（位置序，1 起；顺序锁死）
- `startFrame: Int` / `endFrame: Int`（**源视频绝对帧号**，与 `Segment` 同一 fps 基准，保证切片对齐）
- `variants: [ShotVariant]`（关系；cascade 删除）
- `selectedVariantID: UUID?`（该坑选定版本；`nil` = 用原分镜头）
- 派生：`startTime/endTime/duration`（由帧号/fps 计算，仅显示用）

> 分镜头**按需持久化**：仅在用户进入某逻辑分镜的工作区时才切分并存；不在导入流水线里全量切。

### 4.2 新增 `ShotVariant`（@Model，对标现有配音变体范式）

- `id: UUID`
- `shot: PhysicalShot`（关系）
- `prompt: String`（用户提示词，必填）
- `status: ShotVariantStatus`（`pending` / `uploading` / `generating` / `completed` / `failed`）
- `taskId: String?`（DashScope 异步任务 id）
- `resultVideoPath: String?`（下载落地的 mp4 路径）
- `thumbnailPath: String?`（变体首帧缩略图，供选择时预览）
- `friendlyError: String?`（失败时透出的真实原因，翻译 DashScope 错误码 + 附原文）
- `createdAt: Date`

### 4.3 合成分镜：复用现有 `Segment`

- 合成 mp4 = 新文件 → 建一个新 `Video` 实体（按 hash 落 `AppSupport/MixCut/Videos/{hash}/`）→ 新 `Segment.video` 指向它，`startFrame=0`、`endFrame=末帧`。
- **继承**：`text`、`semanticTypesData`、`keywordsData`、`positionType`、`visualDescription` 从原逻辑分镜拷贝。
- **新增字段** `sourceSegmentID: UUID?`（可选；标记来源，仅追溯用，不影响并存与下游）。
- 这样合成分镜对下游而言是一条"普通导入分镜"，**排列组合/配音/字幕/导出无需改造**。
- **库内摆放（用户明确要求"紧挨原分镜之后"）**：合成分镜有自己的新 `Video`（承载拼接 mp4），但分镜库当前按**源视频分组**渲染，新视频会落到独立分组。为满足"紧挨原分镜之后"，需改 `SegmentLibraryViewModel` 的分组：**带 `sourceSegmentID` 的合成分镜，其展示归属跟随 `sourceSegment` 所在的源视频组，并在组内排在 `sourceSegment` 紧后面**（播放/切片仍用它自己的 `video`；仅"展示分组归属"改为跟随来源）。此改动触及敏感的库视图，须按 CLAUDE.md 做回归验证。

> **Schema 变更**：新增 2 个 @Model + `Segment.sourceSegmentID` + `Segment.physicalShots` 反向关系。变更前必须按项目规则备份 `MixCut.store`。项目未用 VersionedSchema，需评估兼容性（新字段均可选/新表，风险较低，但仍要备份验证）。

## 5. 模型接入（`wan2.7-videoedit`）

### 5.1 接口事实（需在实现首日以控制台/实测核对）

- **模型 ID**：`wan2.7-videoedit`（**北京区命名务必核对**——旧文档踩过 `wanx2.1-` vs `wan2.1-` 的坑，本 model-id 同样以控制台为准）。
- **端点**：`POST https://dashscope.aliyuncs.com/api/v1/services/aigc/video-generation/video-synthesis`（北京区）
- **查询**：`GET https://dashscope.aliyuncs.com/api/v1/tasks/{task_id}`
- **必需头**：`Authorization: Bearer KEY`、`Content-Type: application/json`、`X-DashScope-Async: enable`。
- **鉴权 key**：复用现有千问 DashScope key（同属 DashScope）。
- **输入参数**：`media`（视频，**必填**，支持 URL 或 Base64）、`prompt`（文本指令，本 UI 中我们强制必填）、`reference_image`（可选，本版**不使用**）。
- **输出时长**：`duration` 默认 `0` = 用输入时长不截断 → **进多少秒出多少秒成立**。首日实测确认：是否需显式传 `0`；模型对**下限 2s**（乃至更短分镜头）是否真的接受、输出时长与输入的实际帧数偏差（见 §8.2 帧数对齐）。

### 5.2 输入/输出硬约束

| 项 | 值 | 来源 |
|---|---|---|
| 输入格式 | mp4 / mov | 文档 |
| 输入分辨率 | 宽高 [240, 4096] px | 文档 |
| 输入宽高比 | 1:8 ~ 8:1（竖屏 9:16 在内） | 文档 |
| 输入文件大小 | ≤ 100MB | 文档 |
| **输入/输出时长** | **[2s, 10s]，输出=输入** | 文档 |
| 输出音频 | **可能无声**（VACE 实测无声，wan2.7 待实测）→ 设计上不依赖 | §1.1 |
| 结果 URL | **24h 过期** → 拿到立即下载落本地 | 旧 findings |

### 5.3 媒体传输：优先 Base64，兜底临时上传

- **首选**：分镜头切片一般 2~10s 竖屏短片，几 MB，直接 **Base64 内联** 进 `media`，省去外部可达 URL 问题。
- **兜底**：若 Base64 体积/接口有限制，用 DashScope 临时上传拿 `oss://` URL（`GET /uploads?action=getPolicy` → form-data POST → `oss://`，48h 有效；用 `oss://` 时加头 `X-DashScope-OssResourceResolve: enable`）。
- 具体走哪条，实现首日实测 Base64 是否被 `wan2.7-videoedit` 接受后定。

### 5.4 异步与错误处理（复用现有骨架）

- 完全复用现有配音的「建任务 → 轮询 → 状态机 → 真实错误透出」骨架（参考 `DubExportService` / `FFmpegRunner` 的异步/取消模式）。
- 轮询间隔 ~15s，任务 ~2 分钟级；UI 明示"生成中 / 预计耗时 / 可能计费"。
- 失败：`friendlyError` 翻译 DashScope 错误码 + 附原文，不能只显示"失败"。
- 结果完成后**立即下载** mp4 到本地（URL 24h 过期），落 `AppSupport/MixCut/ShotVariants/{shotId}/{variantId}.mp4`。

## 6. 分镜头切分与可编辑资格

- **切分依据**：复用 `SceneDetectionService` 的画面变化度 `scene_score`（FFmpeg `select='gt(scene,阈值)',metadata=print`），在逻辑分镜的时间段内切出连贯分镜头。
- **帧级微调**：切出的分镜头边界可手动逐帧调整（复用现有边界微调 UI）。允许相邻分镜头合并/边界拖动，以便把过长/过碎的分镜头调进可编辑范围。
- **可编辑资格规则**：分镜头时长 `d` 满足 `2s ≤ d ≤ 10s` 才允许生成变体。
  - `d > 10s` 或 `d < 2s` → 「替换」按钮**置灰 + 提示**（如"该分镜头 12.3s 超过 10s 上限，请用帧级调整拆短后再替换"）。
  - 资格不影响占位：不可编辑的分镜头照样占一个坑，只能选**原版**。
- **切片规范**（生成变体前对分镜头切片时保证）：mp4、分辨率/宽高比落在 §5.2 范围、≤100MB。切片用 FFmpeg trim + setpts 重置时间戳（复用现有导出经验，避免首帧黑屏）。

## 8. 合成（新逻辑分镜产出）

1. 按 `orderIndex` 收集每个坑选定的切片来源：原分镜头 = 从源视频 trim 出的切片；变体 = 其 `resultVideoPath`。
2. **规范化（含严格帧数对齐）**：变体输出可能与原切片 fps/分辨率不同（如输出 30fps/720p），concat 前用 FFmpeg 统一 fps/分辨率/像素格式。**关键**：编辑模型输出时长并非逐帧严格等于输入（旧 findings 实测 3.2s 输入→3.23s/97 帧输出，有几十毫秒漂移）。多个坑串接时漂移会**累积**成整条合成分镜的音画渐进错位。因此规范化必须把每个选定切片（原分镜头切片 & 变体切片一律）**trim/pad 到与该分镜头原始帧数完全相同**（多退少补，pad 用重复末帧或黑帧按需定），保证 §8.4「合回原音频」的"各坑等长、逐帧对齐"前提成立。
3. **拼接**：FFmpeg concat 得到画面轨（复用现有导出拼接链）。
4. **合回音频**：从原逻辑分镜对应时间段提取原音频（连续、含 BGM 与人声），**替换/覆盖**到拼接画面上（因各坑与原分镜头**等长**，音画逐帧对齐）。**一律使用原音频，不依赖变体音轨**（规避编辑模型无声/异常音的问题）。
5. 产出 mp4 → hash 落 `Videos/{hash}/` → 建新 `Video` + 新 `Segment`（继承标签、`sourceSegmentID` 指回原分镜）→ 插入库中原分镜之后。

## 9. 复用的现有能力

- `SceneDetectionService`：`scene_score` 画面变化度（切分镜头）。
- `FFmpegRunner` / 现有导出拼接链：切片、规范化、concat、trim+setpts。
- 配音异步骨架（`DubExportService` 模式）：建任务/轮询/状态/取消/`friendlyError`。
- `ThumbnailCache.shared`：分镜头/变体缩略图（禁止重新引入同步 `NSImage(contentsOfFile:)`）。
- 边界微调 UI（`BoundaryAdjustRow`）：分镜头帧级调整。
- Toast / InlineBanner / SkeletonView：错误提示与 loading。
- 切换项目联动：工作区/库视图遵循 `.task(id: project.id)` 铁律。

## 10. 风险与验收项（按优先级）

1. **【命门 / 第一验收项】局部指令保真度**：`wan2.7-videoedit` 文档只演示了"整体风格转换"和"带参考图换衣"，**未承诺**"换发型/换睡衣颜色/换背景画/换特定物体"这类**纯文字、细粒度、只改目标其余不动**的能力。**实现首日必须用 §7 的 4 个示例实测一版**，确认能"只改目标、人物动作/其余画面/整段一致"再铺开；若发现"顺手改坏别处"，回退考虑框选精确模式（未来增强）。
2. **输出音频行为待实测**：编辑模型可能无声。设计已防御（一律合回原音频），但需实测确认输出可正常被 FFmpeg 处理、时长严格等长。
3. **model-id / 端点 / 参数以控制台为准**：北京区命名有历史坑；实现首日核对 `wan2.7-videoedit` 是否存在、参数名（`media`/`prompt`/`duration`）是否一致、Base64 是否被接受。
4. **计费**：按输出秒数计费，官方未给确定单价，需控制台确认；UI 明示可能计费。**注**：旧 findings 的"先出便宜图片预览、选定后再花钱跑视频"省钱闸门在本方案**被去掉**（`wan2.7-videoedit` 无图片预览环节，纯提示词直出视频）——这是模型切换的合理后果，非遗漏。若后续计费偏高，可考虑"生成前二次确认"作为轻量预算闸门。
5. **分镜头切分粒度**：`scene_score` 阈值可能切太碎/太粗；帧级调整 + 合并作为兜底，阈值可留可调。
6. **Schema 兼容**：新增模型/字段前备份 `MixCut.store`，验证旧库可加载。
