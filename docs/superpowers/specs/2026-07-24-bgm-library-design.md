# BGM 库 + 导出 BGM 替换 设计方案

**日期**: 2026-07-24
**状态**: 已与用户确认

## 需求

现有流程完全不变，新增：

1. **全局 BGM 库**：用户上传 MP3 文件，所有项目共享。
2. **导出时可选 BGM**：成片导出时可从 BGM 库选一条。
   - **不选**（默认，UI 文案「保留原 BGM」）：现有行为，各分镜原音轨直接拼接。
   - **选了**：成片音频 = 各分镜**纯口播**（去掉原 BGM）拼接 + 选中的 BGM 整片铺底。BGM 比成片长则截断，比成片短则无缝循环，结尾 1 秒淡出。

## 核心原则（用户明确要求）

**兜底只能兜「过程」，不能兜「结果」**：

- 选了 BGM，成片就必须是「纯口播 + 该 BGM」。任何导致效果达不到的失败（如人声分离失败）→ **该成片导出直接失败**，错误信息写清哪个视频、哪一步、什么原因（真实报错翻译后透出，参照批量配音的 friendlyError 做法）。
- 允许的兜底仅限不改变成片效果的（如 GPU 失败回退 CPU，只是变慢）。
- 一个视频分离失败只影响用到它的成片，不影响其他成片。

## 设计

### 1. BGM 库（存储 + 管理）

- **存储**：不动 SwiftData schema。MP3 复制到全局目录 `AppSupport/MixCut/BGM/`，列表即目录扫描，文件名即显示名。重名自动加后缀。
- **上传校验**：AVFoundation 校验是有效音频，无效文件报错拒收。
- **入口**：侧边栏新增「BGM 库」导航项。界面：上传按钮（可多选）+ 列表（文件名、时长、试听播放、删除）。

### 2. 导出页 BGM 选项（ExportView）

- 导出设置新增「背景音乐」区块：默认「保留原 BGM」（文案定稿，不用「保留原声」以免歧义）；下拉选 BGM 库中一条；BGM 音量滑杆（默认 60%，避免压过口播）。
- 选中后作用于本次导出的**所有成片**，包括配音组合变体。

### 3. 混音逻辑

选了 BGM 时，每条成片音频构成：

- **普通分镜**：取该视频 demucs 分离的 `vocals.wav`（纯口播）按分镜时间切片。复用现有 `VocalSeparationService` 的分离与缓存（同一视频只分离一次，键 = videoHash）。未分离过的视频导出时自动先分离，进度提示「正在分离人声」。
- **配音分镜**：直接用克隆配音人声（本身纯人声），**不再**混原视频分离 BGM。
- **整片 BGM**：口播轨拼好后铺选中 MP3，长截短循环，结尾 1s 淡出（afade）。

### 4. 边界（本期不做）

- 分镜素材库「批量导出单个分镜」不加 BGM 选项，BGM 仅作用于成片导出。
- 不做 BGM 入点选择、分段换 BGM、自动卡点。

## 涉及模块（预估）

- 新增：`BGMLibraryService`（目录扫描/上传/删除）、`Views/BGMLibrary/`（管理界面）
- 修改：`NavigationItem`（新导航项）、`ExportView`（BGM 选择区块）、`ExportService` / `DubExportService`（混音管线加「纯口播 + 全局 BGM」模式）
- 复用：`VocalSeparationService`（demucs 分离与缓存）、`FFmpegRunner`
