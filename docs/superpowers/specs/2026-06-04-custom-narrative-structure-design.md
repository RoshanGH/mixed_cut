# 自定义叙事结构 — 设计文档

- 日期：2026-06-04
- 状态：设计已确认，待写实现计划
- 范围：MixCut「混剪方案」区新增「自定义叙事结构」功能

## 一、背景与目标

现有能力：
- 成片已能按语义切分镜，并由 AI 两步生成混剪方案（Step 1 AI 生成策略含叙事结构 → Step 2 AI 按策略挑分镜组合）。
- 「自定义组合」支持用户在分镜库手动挑分镜拼成方案。

本功能目标：让用户**先用系统标签定义一条叙事结构（有序段位，每段一组标签），再由 AI 在每段的候选分镜里挑片、生成多个变体，并经台词连贯性校验后只保留通过的**。本质是把现有"两步生成"的第一步从"AI 定策略"换成"用户定结构"，复用第二步的选片能力。

核心原则（用户强调）：
- **一切绑定系统标签**：每段只能选系统已有的 SemanticType 标签，不允许手动起名；可选标签**只能是当前项目素材库里真实存在分镜的那些类型**（没素材的类型不可选）。
- **台词连贯**：组装后必须校验整条成片台词（ASR）上下文连贯、符合信息流广告叙事；并**避免"同标签但台词先后被排反"**（如同一句话上/下半句顺序颠倒）。

## 二、层级与命名（三级）

「自定义组合」是两级；「自定义结构」多一级：

```
方案
├─ ▸ AI策略·快节奏种草            (现有)
│     变体1  变体2  变体3
├─ ▸ 自定义组合                   (现有)
│     变体1  变体2
└─ ▾ 自定义结构                   ← 新增「模块/大分类」
      ├─ ▸ 痛点 · 产品展示 · 效果对比/用户证言 · 行动号召   ← 结构A(二级目录)
      │      变体一  变体二  变体三                          ← 该结构生成的变体
      ├─ ▸ 开门见山 · 用户证言 · 行动号召                    ← 结构B(二级目录)
      │      变体一  变体二
      └─ ＋ 添加结构
```

命名规则（全自动，无手填）：
- **二级目录名 = 各段标签按顺序拼接**。段间用 ` · `，同段多标签用 `/`。
  例：`痛点 · 产品展示 · 效果对比/用户证言 · 行动号召`。
- **变体名 = 「变体一、变体二、变体三…」** 顺序编号，无单独 title。
- 无"结构名称"输入框——结构的名字就是它的段位序列本身。

## 三、数据模型

复用现有实体，**不新增 SwiftData 表、不触发 schema 迁移**：

- 每个"结构" = 一个 `MixStrategy`，新增布尔标记 `isNarrativeTemplate = true` 与「自定义组合」(`isCustomGroup`)、AI 策略区分。归在侧边栏"自定义结构"分组下显示。
- 段位序列以 JSON 挂在该 `MixStrategy` 上（参照现有 `semanticTypesData: Data?` + 计算属性的做法，新增 `narrativeSlotsData: Data?` + 计算属性 `narrativeSlots: [NarrativeSlot]`）。
  ```
  struct NarrativeSlot: Codable {
      var order: Int            // 段顺序，0-based
      var tags: [SemanticType]  // 该段选中的系统标签（≥1）
  }
  ```
- `MixStrategy.name` = 由 `narrativeSlots` 自动拼接生成的二级目录名（写入时计算并存储，标签变更时重算）。
- 变体 = 现有 `MixScheme`，复用现有方案列表/详情(`SchemeDetailView`)/导出，无新界面。

## 四、编辑器 UI

入口：方案区侧边栏"自定义结构"分组下的 `＋添加结构`，进入"叙事结构编辑器"。

```
┌─ 叙事结构编辑器 ─────────────────────────┐
│ 预览名: 痛点 · 产品展示 · 行动号召          │  ← 实时由下方段位拼接，只读
│ ┌────────────────────────────────────┐  │
│ │ ① 标签: ⊕痛点 ⊕情绪痛点  ＋加标签  候选8 🗑│  │
│ │ ② 标签: ⊕产品展示        ＋加标签  候选5 🗑│  │
│ │ ③ 标签: ⊕行动号召        ＋加标签  候选3 🗑│  │
│ └────────────────────────────────────┘  │
│            ＋ 添加一段                      │
│ 生成变体数: [ 5 ▾ ]        [ 生成方案 ]      │
└──────────────────────────────────────────┘
```

交互：
- 每段一行：可拖拽排序、可删；显示**候选数**（实时随标签变化更新）。
- `＋加标签`：弹出**只列当前项目库里真实有分镜的 SemanticType**；已选以 chip 显示，可点 × 移除。
- 段无标签 / 候选为 0 → 该段标红，`生成方案` 禁用并提示。
- 预览名 = 段位标签实时拼接，只读。
- 点 `生成方案` → 跑生成流水线 → **通过校验的变体并入右侧现有方案列表**（归在该结构名下），复用现有预览/微调/导出。
- 生成时按钮 loading + 进度文案（复用现有 `isGenerating`）。

## 五、生成流水线

1. **算候选池**：对每段，候选池 = 项目库里"分镜的 `semanticTypes` ∩ 该段标签 ≠ 空"的分镜（标签取并集）。
2. **前置校验**：
   - 某段候选为 0 → 阻止生成并提示。
   - 按各段候选数计算**可行变体上限**（见 §6 第 4 点）；用户请求数超上限则取上限并提示。
3. **AI 选片组变体**：见 §六提示词。每段从该段候选挑 1 条，生成 N 个变体；选片参考台词衔接，变体间去重（沿用现有 fingerprint 思路）。
4. **连贯性 + 顺序校验**：见 §六。**只保留通过的**。
5. **落库展示**：通过的变体存为 `MixScheme`，挂在该结构（`MixStrategy`）下，命名"变体一/二/三…"。

## 六、AI 提示词设计

### 6.1 喂给 AI 的数据
复用现有片段目录格式（已含台词）：`ID | 位置 | 类型 | 时长 | 台词`。差异：按"段 → 候选列表"组织，而非全量素材池。

### 6.2 调用策略：先单次，不达标切两次
- **默认单次合并调用**：AI 一次完成"按候选池选片 + 自检连贯性 + 只输出通过的"。省 token、更快。
- **风险**：同一 AI"既挑又判"易放水（倾向都说连贯）。
- **回退**：若实测出现"什么都说连贯"，立即拆为两次——调用1 只按候选池产出 N 变体；调用2 把每个变体台词拼接做**独立严格打分**（分数+原因），低于阈值刷掉。

### 6.3 单次提示词草案

```
你是信息流广告混剪专家。下面是一个固定的「叙事结构」(若干段,顺序不可变),
每段给了一组候选分镜。任务:为每段从它自己的候选里挑 1 条,组成成片;
生成 N 个不同变体;对每个变体做台词连贯性自检,只输出连贯的。

## 叙事结构(段顺序=成片顺序,固定;你只决定每段选哪条)
段1 [标签:痛点/情绪痛点] 候选:
  V1_03 | 2.1s | 台词:"天天熬夜皮肤越来越差…"
  V2_01 | 1.8s | 台词:"你是不是也有这种困扰"
段2 [标签:产品展示] 候选:
  V1_05 | 3.0s | 台词:"这款精华含有…"
  …
段3 [标签:效果对比/用户证言] 候选: …
段4 [标签:行动号召] 候选: …

## 硬性规则
1. 每段必须且只能从【该段自己的候选】里选 1 条;不能借别段候选、不能漏段、不能改段序。
2. 同一变体内不得重复使用同一条分镜(某条同时出现在两段候选里时,只能用在一段)。
3. 生成 N 个变体,彼此要有差异,不得有两个完全相同的 ID 组合。
4. 连贯性自检——只输出通过的,不通过的直接丢弃:
   a. 相邻段台词语义衔接,整体像一条完整口播,不跳脱;
   b. ⚠️ 台词逻辑顺序不能排反:若两条台词本身有先后(同句上/下半句、"首先…其次…"),
      后半不能排在前半之前;
   c. 整体符合信息流节奏(开头抓人→中间种草→结尾促单)。

## 输出(JSON,只含通过自检的变体)
{"variants":[
 {"segments":["V1_03","V1_05","V2_07","V1_09"],"note":"痛点→产品→证言→促单,台词顺承"}
]}
只输出 JSON。
```

### 6.4 已确认的约束
1. **候选截断**：每段最多列 Top N 条（按质量/时长排序，默认 N=30），超出截断并提示。防止 prompt 过大/超限。
2. **"台词排反"靠 AI 语义判断**：列为自检红线，提示词强调 + 喂台词，**尽力而为**，不保证 100%，靠校验拦截大部分。
3. **变体上限自适应**：按各段候选数算可行上限，请求数超限则取上限并提示。

## 七、错误处理

- 某段无标签 / 候选为 0：编辑器禁用生成并就地提示，不发请求。
- AI 返回解析失败：沿用现有 Step 2 做法（本批跳过、记日志、不重试烧 token）。
- AI 选了不在候选池里的分镜 / 重复用同一分镜：**程序侧二次校验过滤**，剔除非法变体（不能只信 AI 自觉）。
- 全部变体均未通过校验：提示"未生成连贯变体，建议调整段位标签或增加素材"，不留空壳。
- 候选截断时：提示"第 X 段候选过多，仅取前 30 条参与生成"。

## 八、测试要点

- 候选池计算：标签并集、库内类型过滤（无素材类型不出现）。
- 变体上限计算：各段候选数 → 可行去重组合上限。
- 程序侧校验：剔除"选了非候选/重复分镜/段数不符"的非法变体。
- 二级目录名拼接：多段多标签的 ` · ` / `/` 规则。
- 切项目联动：切换项目时编辑器候选/结构随项目刷新（遵守 CLAUDE.md "切换项目铁律"）。
- 真机交互验证：编辑器加标签/拖拽排序/生成、变体进入详情页样式与现有方案一致。

## 九、暂不做（YAGNI）

- 跨项目"结构模板"复用 / 另存为模板。
- 变体单独命名、结构手动命名。
- 两次调用的严格打分（仅在单次放水时才启用，作为回退方案）。

## 十、复用与改动清单（概览）

- `MixStrategy`：+`isNarrativeTemplate`、+`narrativeSlotsData` + 计算属性、name 自动拼接。
- `SchemeGenerationService`：+按"段→候选池"组织目录的方法、+叙事结构选片提示词、+程序侧合法性校验；复用现有批量/去重/解析。
- `SchemeViewModel` / 方案侧边栏：+"自定义结构"分组与三级展示、+编辑器入口。
- 新增叙事结构编辑器视图。
- 变体详情/导出：零改动，直接复用 `SchemeDetailView`。
