# MixCut 优化日志

> 从 2026-07-09 起的一轮轮优化记录。**每项改动都编译+重启+截图自测、不改坏已有功能、不自动提交**（攒着供验收）。基线：commit `51c4609`。

## 原则
- 一轮一个聚焦点，改动小、可独立回退。
- 高敏感组件（SegmentInlinePlayer hover 播放 / RangeVideoPlayer / 导出流水线 / 边界微调 / ASR）非必要不动；要动必全量自测。
- 9:16 竖屏、universal、切项目联动、强制浅色 等铁律不破。

---

## Round 1 · 性能实测（诊断，无代码改动）
- 分镜库静置：**0% CPU**，无 idle 渲染死循环。
- 悬停快速扫过 30 张卡片：瞬时 **36–61% CPU**，停手立即回落 0%。
- 定位：来自库卡片 hover 时的富交互 UI（BoundaryAdjustRow 的多 TextField + `withAnimation` 动画）+ SegmentInlinePlayer 视图切换。**该组件已做多重优化**（轻量缩略图默认态、0.35s hover 防抖、BoundaryAdjustRow 仅 hover 显示）。
- 结论：瞬时尖峰属富 hover UI 的固有成本、非 bug；该组件历史上一改就坏，**不为瞬时尖峰冒险动它**。性能无明显可安全修的 bug。

## Round 2 · 概览页 + 侧栏 安全修复（已编译+重启+截图验证 ✅）
1. **修复 9:16 铁律违反**：`ProjectOverviewView.VideoCard.videoAspectRatio` 元数据缺失时兜底从 `16:9` 改为 `9:16`（与导入页一致）。
2. **StatCard 计数为 0 不再"假装可点"**：分镜/方案卡片计数为 0 时传 `onTap: nil`（真禁用），并让禁用态不再 hover 高亮/放大。
3. **归档项目加 Toast 反馈**：`SidebarView` 右键归档后 `ToastCenter.show("已归档「…」")`，与重命名反馈一致（此前归档静默、易被误以为删除）。
- 验证：概览页截图布局正常、无回归。

- 说明：这两处分别只在首启 Onboarding / 抽屉选择器出现，难截图；均为文案/等价重构，编译通过即安全。

## Round 5 · 性能：多选栏已选时长轻量化（已编译验证 ✅）
- 多选工具栏常驻显示「已选 N 个 · X.Xs」，原来读 `selectedSegments`（filter 建数组 + sorted + `uuidString` 分配）只为求和，排序纯浪费。
- 新增 VM 轻量 `selectedDuration`（一次 reduce 求和，不建数组不排序），视图改用它。行为一致。
- 验证：库渲染正常无回归（多选态坐标没点中、未截到工具栏，但改动逻辑等价、编译通过）。

## Round 6 · 删除策略/变体加二次确认（已编译验证 ✅）
- 方案页右键「删除策略/结构」「删除变体」原来即删、不可恢复、无确认，与删视频/项目/批量删分镜的确认模式不一致。
